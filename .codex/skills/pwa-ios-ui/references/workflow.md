# 生成与交付流程

## 准备

1. 识别目标产品、页面关系、入口与完成路径，读取适用的项目说明、设计令牌和现有组件。仅缺少会实质改变产品的信息时提问。
2. 检查可用 React、React DOM、Konsta、Tailwind、Vite 及 Tailwind Vite 插件的版本；模板构建方式面向 Tailwind 4 和提供 theme.css 的 Konsta。其他版本先适配实际构建方式，不静默升级目标项目。
3. 将 assets/template 中三个文件复制到输出目录，调整页面与模拟数据。复用目标项目已有依赖；若没有兼容依赖，在独立预览目录配置并安装，保留清单和锁文件，遵守环境网络权限，不改生产依赖。

## 构建

在有兼容依赖可解析的目录执行：

```sh
node previews/<feature-slug>/build.mjs
```

脚本通过 Vite 与 Tailwind 插件编译 JSX/CSS，将 React/Konsta 打包并内嵌到同目录 preview.html。也可将输出 HTML 路径作为第一个参数，用于临时验证。不要手写模拟组件来绕过构建问题。

模板无需 CDN、浏览器 Babel 或运行时 Tailwind。新增图片、字体或其他资源时保证可内嵌；脚本拒绝未处理的额外产物，发现外部资源请求也必须处理后才能声称 HTML 自包含。保留库许可注释。不要为原型注册 Service Worker。

## 实现与验证

- 以 React 状态驱动选中、返回、表单、空态和反馈，导航操作均能完成；模拟状态不要写入真实业务服务。
- 按需求替换整个示例业务，不保留无意义标签或占位按钮。
- 检查单个页面主操作是否为右下角圆形 Fab；不得出现整行按钮或底部背景栏。滚动到底验证末项可避开按钮，同时检查窄屏和安全区。
- 检查所有日期区间只有一个范围字段；在同一日历流程中完成起止日期选择，并验证区间高亮、结束日约束、取消不改值和确认后原子更新。禁止用两个独立日期输入交付效果稿。
- 构建成功后检查 HTML 包含打包脚本和编译 CSS，源码确实导入 konsta/react。
- 有浏览器工具时打开生成 HTML，检查无控制台异常/资源失败、375px 和 390px 布局、浅深模式、吸顶、滚动到底、底栏切换及详情返回。
- 浏览器工具不可用时执行构建和静态产物检查，交付中说明尚未视觉验证。

## 开发交接

handoff.md 记录页面关系和 Tabbar 判定、所用 Konsta 组件及关键 props、模拟数据和状态转移、配色与布局、依赖的实际版本、构建命令及检查结果。只记录已实现的行为，不将未来设想描述为完成。

告诉生产开发哪些本地状态应接入真实路由/store/API，保留 Navbar、平行页 Tabbar 与禁止回弹 CSS 约定。交付先链接 preview.html，再链接可读 JSX 和交接说明。
