# iOS 风格设计建议

除标注的固定规则外，以下为项目没有设计约定时的默认建议。用户设计稿、品牌与项目设计系统指导视觉配置，不预设行业或业务风格；导航组件采用下述固定规则。

## 层级与颜色

- 用标题、分组列表和留白组织内容，信息与操作优先于装饰。
- 列表适合重复记录、设置和字段；卡片适合独立对象、摘要或媒体，避免无意义嵌套。
- 主要操作有清晰优先级，品牌表达集中在关键区域。
- 复用语义令牌；缺少时集中定义背景、表面、文字、分隔线、强调和状态色。
- 无品牌约定时可采用系统蓝与 iOS 分组表面方向，不强制固定色值。
- 危险、成功和警告同时配合文字或图标。浏览器 `theme_color` 和组件品牌色分别核对。

## 字体与布局

- 优先系统字体；已有品牌字体则沿用并考虑加载和离线表现。
- 缺少字号规范时，可从大标题 34px、正文/导航 17px、次级 15px、辅助 13px 起步，按密度和可读性调整。
- 对齐数值可用 `font-variant-numeric: tabular-nums`，不随意增加中文正文的字间距。
- 默认以 4px 步进组织间距，手机左右留白约 16–20px，优先组件默认圆角。
- 触控区域以至少 44 × 44 CSS px 为目标，可扩大命中区而不放大图标。
- 无目标尺寸时以 390 × 844 起步并检查 375px 窄屏；按产品范围适配横屏、平板或桌面，不固定画布。
- 主滚动区域清晰，避免 body 和页面意外双重滚动；有实际用途的独立滚动区另行处理。
- 固定导航和操作区给内容留足空间，安全区由负责区域的布局统一处理。
- Tabbar 按下文的页面关系规则使用，不因页面数量多就添加。
- 键盘打开后字段、错误信息和完成路径仍可访问。

## 单个页面主操作（固定规则）

- 页面只有一个常驻主操作（如创建、添加、记一笔）时，使用右下角圆形悬浮按钮 `Fab`，不设计全宽或接近全宽的胶囊按钮。
- 仅按钮自身具有品牌色背景与轻量阴影；按钮周围透出页面内容，不添加横贯底部的白底、毛玻璃、渐变遮罩、分割线或整行占位容器。
- 采用约 56 × 56 CSS px 圆形、24–28px 图标，距右边约 20px，距底部约 20px 加安全区。添加类动作使用正式加号图标；其他动作使用准确的图标和可访问名称。
- 为滚动内容预留按钮高度、底部间距与安全区，让最后一项可以滚动到按钮上方；若已有 Tabbar，悬浮按钮放在它上方且不重复计算安全区。
- 不给同一个动作同时设置 Fab 和底部大按钮。Fab 不承担导航标签职责。
- 该规则针对页面常驻入口；表单内的保存/确认、弹窗动作及多操作工具栏按各自语义设计，不因为只有一个提交按钮就改成加号 Fab。

## 顶部导航栏（固定规则）

- 导航栏必须使用 Konsta `Navbar`，固定采用 `className="top-0 sticky"`；不得用普通容器、标题和按钮拼装替代。
- 默认使用 Konsta `Navbar` 自带的背景和轻微模糊层，不给整条导航额外加 `backdrop-filter`、半透明渐变或自定义毛玻璃，也不隐藏组件生成的背景层。内容从导航下方开始，不用负边距与导航重叠；用户明确要求特殊顶部设计时按其设计处理。
- 使用组件的 `title`、`subtitle`、`medium`、`large` 及左右操作槽表达页面设计，不另造导航栏尺寸体系。`transparent` 仅在用户明确要求透明导航时使用。
- 导航操作使用 `Link navbar`，返回使用 `NavbarBackLink` 接入实际导航；无副标题或右侧操作时省略对应内容。
- 粘滞定位与页面主滚动容器配合，检查顶部安全区、滚动时的层级和透明背景下的可读性。示例见 [组件规范](konsta-components.md#navbar-固定结构)。

## 平行页面与 Tabbar（固定规则）

- 多个同级、可独立进入且可相互切换的一级页面属于平行页面，例如收件箱、日历、上传中心、我的；使用底部 Tabbar 作为共同导航。
- 非平行页面不设计 Tabbar。例如列表到详情、详情到编辑、创建流程的多个步骤，使用返回导航或流程操作；单页应用也不添加 Tabbar。
- 按页面关系判断，不按页面数量判断。“上传”只有作为独立目的地时才是标签；若只是选择文件或提交动作，应使用按钮。
- 平行一级页面共享同一个 Tabbar；进入非平行的详情、编辑或流程页面时不显示它，避免在全局布局无条件渲染。
- 使用 `Tabbar labels icons`，内部使用 `ToolbarPane` 包裹 `TabbarLink`，固定在底部；结构示例见 [组件规范](konsta-components.md#平行一级页面的-tabbar-示例)。
- 选中态跟随实际路由或页面状态，点击必须切换页面；内容为底栏及安全区留足空间。徽标只展示真实业务数据。

## 交互与可访问性

- 优先内置按压和弹层反馈，自定义动画简短、可中断，尊重 `prefers-reduced-motion`。
- 按任务覆盖加载、空、错误、禁用及危险状态，不为同步操作制造假加载。
- Toast 用于短暂反馈，字段错误靠近字段，必须阅读的信息持久呈现。
- 删除、覆盖和清空说明对象与影响，按可恢复性提供确认或可靠撤销。
- 接入现有系统/手动主题机制，不固定主题文件、provider 或 `.dark` 方案，不重复监听系统主题。
- 自定义颜色、图标和禁用状态检查各支持主题的对比度。
- 输入关联可见标签，图标按钮有可访问名称，选择控件保留真实语义。
- 键盘焦点可见，弹层正确处理焦点、关闭与恢复。
- 正文支持换行与文本放大，关键信息不能因截断丢失。
- 使用目标语言、真实长度的内容及日期/数字格式验证，不硬编码中文或单一货币。
