# PWA iOS 开发

根据目标项目的架构与产品需求实现可维护的 iOS 风格 PWA。技能存放位置不决定目标项目、业务模型或源码路径。

## 适配目标项目

- 从用户指定位置或当前工作目录确定应用根目录；多应用仓库中定位相关包，不把技能目录当作应用目录。
- 读取适用的仓库指引、包配置和相关源码，识别技术版本、包管理器、路由、状态、主题、样式、构建与 PWA 方案。
- React、TypeScript 和 Konsta UI 是主要技术范围，不固定 React 主版本、构建工具或目录结构。按已安装版本核对 API。
- 已有项目沿用现有架构。缺少 Konsta 或 PWA 集成时，判断补充是否属于需求，不因调用技能自动迁移技术栈。非 React 项目仅应用适用的设计和 PWA 原则，并说明技术范围。
- 从零建设且未指定方案时，可采用 React + TypeScript + Konsta UI，根据部署需求选择构建、路由及 PWA 集成，不默认引入账号、后端或同步。

## 按需读取

- 修改生产代码：读取 [开发工作流](references/development-workflow.md)。
- 调整界面：读取 [设计建议](references/design-system.md)。用户设计稿与项目设计系统优先，建议只补充缺失约定。
- 选择或组合 Konsta 组件：读取 [组件规范](references/konsta-components.md)。
- 涉及安装、图标、缓存、离线、更新、Service Worker 或 standalone：读取 [PWA 质量清单](references/pwa-quality-checklist.md)，执行相关条目。
- 涉及业务含义：定位项目产品文档、领域类型和数据模块，不假设文件名或行业；明确说明会改变产品行为的文档与代码冲突。

## 固定基础样式

React + Tailwind CSS + Konsta UI 项目直接引用 [assets/index.css](assets/index.css) 作为全局样式基线，放入目标应用的 `index.css`，由应用入口加载。新项目可直接复制；已有项目合并相同规则并保留业务样式，避免重复导入。

- Tailwind 与 Konsta 的两个 `@import` 必须按模板顺序放在同一个全局样式文件中，不能拆到其他样式文件。
- 固定使用模板中的根容器重置与 `overscroll-behavior` 规则，关闭浏览器滚动边界回弹，同时保留页面正常纵向滚动。
- `.k-page` 是 Konsta UI 的 Page 组件默认生成的 CSS 类，直接使用此选择器，不需要另加自定义类。
- 模板的 `#root` 对应 React 挂载节点；目标项目使用其他挂载 ID 时只替换该选择器，其余基础规则保持一致。
- 模板适用于支持所示导入方式的 Tailwind/Konsta 版本；旧版本或未使用该组合的项目先核对兼容性，不静默升级依赖。

## 实现与完成标准

单个页面级主操作（如创建、添加、记一笔）必须使用右下角独立圆形 `Fab`，不使用整行宽按钮或带背景的底部操作栏。按钮自身保留品牌色背景，外围不铺背景；表单内的保存/确认仍使用 `Button`。具体结构见组件规范。

业务字段表示日期区间（如出发至返程、入住至离店）时，必须使用一个日期范围组件完成起止日期选择；不得让用户分别填写“开始日期”和“结束日期”。单日期、日期时间点不套用此规则。具体交互和数据约束见组件规范。

导航采用固定判定：多个彼此平行的一级页面使用 `Tabbar` + `ToolbarPane` + `TabbarLink`；不是平行页面则不设计 Tabbar。具体判定见设计建议，组件结构见组件规范。

顶部导航栏必须使用 `konsta/react` 的 `Navbar`，采用 `className="top-0 sticky"`，不得用自定义 HTML/CSS 模拟导航栏。标题、尺寸、透明效果及操作槽按组件规范配置；已有封装必须以 `Navbar` 为基础。

1. 明确入口、完成路径、数据变化及验收结果，检查现有实现后确定范围。
2. 优先复用业务组件和 Konsta 通用交互，必要时组合业务组件；平台语义或能力不足时采用合适的现有组件或语义化 HTML。
3. 沿用路由、状态、持久化、主题和样式机制，避免并行状态源、重复主题监听及 Service Worker 注册。
4. 覆盖相关的加载、空、错误、禁用和危险操作状态，保护未提交输入与已有数据。
5. 按目标项目要求运行静态检查、测试和生产构建；可见改动检查窄屏、主题、安全区及键盘行为，明确未验证项。
6. 交付行为变化、主要文件、验证结果，以及实际存在的依赖、配置、缓存或迁移影响。

局部需求不扩展为无关重构。依赖、路由或部署调整应直接服务需求。效果图仅作为视觉输入，生产代码放入正常应用结构，不依赖其他效果图技能。图标复用项目库或 SVG。不手工编辑构建输出，生成资源是否入库遵循项目约定。
